Claim-Verify RAG

Completed, Oct 2026 Solo project Source

What it does

A RAG system that does not trust its own answer. It drafts a cited answer, splits it into atomic claims, and re-checks each claim independently against every source. Each claim gets a verdict with the passages it was judged on: supported, contradicted, unverifiable, or contested when the sources disagree with each other.

How it's built

PostgreSQL + pgvector with local bge embeddings, hybrid search (meaning + BM25) with a cross-encoder reranker, per-document retrieval so every source is heard, and a LangGraph verification loop whose judge is a different model family from the drafter. Every stage is swappable from one config file, and a FastAPI + React UI replays recorded runs and streams live ones.

Results

37/44
claims whose proof reaches the judge, up from 23/44
9/10
verdicts correct on a hand-checked gold set, with no false contradiction

Every change was measured against a rule fixed in advance. The gain in retrieval came from hybrid search and the reranker.

Python, LangGraph, PostgreSQL, pgvector, bge embeddings, BM25, cross-encoder reranker, Groq, Pydantic, FastAPI, React, TypeScript

Recruitment Email → JSON

Completed, Oct 2026 Solo project Source Model

What it does

Fine-tunes Qwen3-4B with QLoRA to turn French, English or mixed recruitment emails into a 10-field JSON record validated against a schema: email type, company, contract, interview stage, sender role, and the deadline, resolved from the Date header (avant vendredi becomes a date).

How it's built

A synthetic data pipeline: specs sampled in Python, emails written by one generator model and blindly relabeled by another (92% full-record agreement), and an n-gram leakage check between train and test. Trained on one free Colab T4 (4-bit base, LoRA r16), checkpoint chosen on validation loss, adapter published on Hugging Face with a Gradio demo.

Results

83.5%
full-record exact match on 200 synthetic test emails, up from 22.5% few-shot (95% CI 78–88.5%)
80%
on emails written by a different model than the training data

Labels are not hand-reviewed yet; the README documents what failed.

Python, PyTorch, Transformers, PEFT, TRL, bitsandbytes, Qwen3, JSON Schema, Gradio, Hugging Face Hub
