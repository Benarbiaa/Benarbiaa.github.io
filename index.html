Claim-Verify RAG

In progress Solo project Private, shared on request

What it does

An agentic RAG system that does not trust its own answer. It drafts a cited answer, splits it into atomic claims, and re-checks each claim independently against every source. Each claim gets a verdict with the passages it was judged on: supported, contradicted, unverifiable, or contested when the sources disagree with each other.

How it's built

PostgreSQL + pgvector with local bge embeddings, per-document retrieval so every source is heard, and a LangGraph verification loop whose judge is a different model family from the drafter. Every stage is swappable from one config file, and a FastAPI + React UI replays recorded runs and streams live ones.

Next

Evaluation: a labelled gold set of claims, per-verdict precision and recall, and a false-contradiction rate, then ablations across retrieval settings and models.

Python, LangGraph, PostgreSQL, pgvector, bge embeddings, Groq, Pydantic, FastAPI, React, TypeScript

OCR Invoice Parsing API

Completed · Jan 2026 Duo project Source

What it does

A FastAPI service that turns invoice images into structured JSON. A custom-trained YOLOv5 model locates the supplier, date, total, and item-table regions; Tesseract reads each crop, and regex parsing maps French fields such as SIREN/SIRET and addresses. An optional Donut model does end-to-end parsing.

Details

Training labels converted from the FATURA invoice dataset (PDF coordinates to YOLO format), automatic dark-image inversion before OCR, and a single Docker image for deployment.

Python, FastAPI, YOLOv5, Tesseract, Donut, PyTorch, OpenCV, Docker
